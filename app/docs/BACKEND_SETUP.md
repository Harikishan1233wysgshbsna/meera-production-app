# Isolated backend installation

1. Back up and export current deployed LIVE script/Sheet separately. Compare it to GitHub; do not paste this candidate over LIVE. Create separate TEST copies and replace every spreadsheet ID in the TEST backend configuration, including master/planning/tracking dependencies. Test accounts and machines only.
2. In TEST, use matching Production Data Sync.gs, one matching cloud.gs (provided here as backend/CloudQueue.gs), ServerRecoveryV2.gs and existing dependencies. Do not install two copies of the same functions or both cloud.gs and CloudQueue.gs.
3. Apply `backend/integration.patch` to the matching TEST `Production Data Sync.gs`. This is an actual unified diff from the inspected revision; `git apply --check`/`patch --dry-run` first. It routes nativeMe/nativeRpc/nativeAuthorize/nativeBatch to the new adapter and parks/skips permanent recovery failures. Add `backend/NativeApp.gs` as another Apps Script file.
4. Run `rc5NativeInitializeTickets()` as TEST owner. This initializes a private random signing secret in Script Properties, without creating a trigger. Never copy that property into GitHub/app config.
5. Inspect existing TEST triggers. Reuse one recognized V2 or reconcile trigger, if present. If none, use the matching cloud installer once. Do not also run the other trigger installers. Check actual Executions and authorization; a trigger's mere existence is not proof of success.
6. Deploy a TEST Web App executing as its owner and allow access suitable for your application login. The application session check remains mandatory. The native clients perform HTTPS POST and follow Apps Script redirects to JSON; Google-level access gates returning HTML must fail as unverified responses. Authorize Google Sheets, triggers and Script Properties scopes requested by the actual TEST code; do not broaden scopes blindly.
7. In the app startup settings, enter only the TEST `/exec` URL, confirm isolation, then open the RC5 form. Username/password challenge login uses existing RC5 routes through nativeRpc; nativeMe revalidates before vault persistence. Native save batches never call the old no-cors writer.
8. Confirm test saves land only in TEST BACKUP/Production. Verify tokens absent from BACKUP payload, exact same-ID replay, different-ID same-Box DUPLICATE policy, a bad row beside good rows, lost response, auth expiry, and worker processing with phone closed.
9. Use the device matrix in VERIFICATION.md. Production deployment and store signing remain a separate reviewed operation; none is done by this project creation.

Native API response contract: `{ok:true, protocol:1, results:[{requestId,owner,box,machine,digest,state,errorCode?}]}`. Batches carry 1–10 envelopes with requestId, canonical payloadJson and digest. Android sends the current owner token in memory; iOS sends an expiring exact-batch ticket. Status polls resubmit immutable input and are idempotent. Unknown/missing/duplicate receipts never count as success.

Do not remove required machine, active-user, deleted-record or payload checks to speed up saves. Apps Script/Sheets quotas are account-dependent. Batching reduces request overhead but does not make Sheets an unlimited database; measure realistic concurrency and recovery backlog on TEST before relying on 200+ entry loads.
